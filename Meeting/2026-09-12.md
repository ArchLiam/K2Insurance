## 핵심 결정 사항

1. **그룹헬스 리뉴얼 이메일은 회사 이름을 제목에 넣고, 갱신 조건은 새 Quote에서 가져오도록 수정합니다.** Carrier에는 보험사가 표시되어야 합니다.
2. **Commercial·Group Health 리드에 상담 단계에서 받는 회사 정보를 입력할 수 있도록 보완합니다.** 요청 항목은 Description, EIN Number, Type, SIC이며, 기존 Address의 회사 주소 사용 여부도 확인합니다.
3. **Agent Management와 커미션 리포트의 기간 기준을 Payment Period로 통일합니다.** Kay가 주원에게 설명하고 리포트 수정을 요청하기로 했습니다.
4. **Agent Payout별 지급 상세 PDF를 확인하는 방향으로 개발합니다.** 개별 고객·보험에 대한 지급 여부를 문의받았을 때 해당 지급 건에서 내역을 확인하는 것이 목적입니다.
5. **Commercial·Group Health Insurance에 해당 Company를 명시적으로 연결하고, 이후 Renewal에도 반영합니다.** 기존 Policy Holder인 Contact 연결과 회사 연결을 함께 유지하는 방향입니다.
6. **Group Health 보험의 Policy Number 입력 화면은 재확인이 필요합니다.** 회의 중 레이아웃을 수정했고 개발자 화면에서는 보였으나, Kay의 Edit 화면에서는 끝까지 확인되지 않았습니다.

- [ ] **Carrier를 Insurance Provider로 연결합니다.** 미리보기에서 Carrier 자리에 고객 회사 이름이 나오는 문제를 수정합니다. BCBS나 UnitedHealthcare 같은 실제 보험사가 표시되어야 합니다.
- [ ] **갱신 안내의 기간·플랜·보험료 등 새 조건은 연결된 Quote에서 가져옵니다.** 현재 템플릿에서 종료 예정인 Original Insurance의 정보가 표시되는 점을 확인했습니다.
- [ ] 수정 후 Kay가 테스트하고, 제목·Carrier·갱신 조건이 의도대로 표시되는지 확인합니다.

**본문 문구:** 담당자 이름을 유지해도 되고, 이름 없이 인사말로 시작해도 괜찮다고 했습니다. 회사 이름은 제목에 있으면 되며 본문에 별도 행을 추가할 필요는 없다고 했습니다.

**사용 전제:** 이메일을 보내기 전에 Renewal에 Quote를 만들고 보험사에서 받은 새 조건을 입력해야 합니다. 여러 Quote가 있을 때 어느 Quote를 참조할지는 이번 회의에서 구체적으로 정하지 않았습니다.

**회의 중 확인:** 템플릿은 Renewal을 기준으로 만들어져 있어 Company에서 찾을 때 보이지 않았습니다. Renewal 목록에서 해당 Opportunity Name을 열고 이메일 작성 화면으로 들어가 템플릿을 삽입·미리보기 하는 방법을 실습했습니다. 테스트 Renewal에 Original Insurance를 연결하자 비어 있던 Policy Holder Name이 표시됐습니다.

- [ ] 실제 사용 후 지급 문의 대응에 필요한 정보가 충분한지 Kay가 확인합니다.

**업무 이유:** 현재 총액만으로는 특정 고객의 보험에 대해 에이전트에게 지급했는지 확인하기 어렵습니다. 에이전트와 지급 기간에 맞는 Payout을 열어 상세 내역으로 답변할 수 있어야 합니다.

**논의의 최종 방향:** 처음에는 Commission Line의 지급 여부 체크박스와 영수증을 함께 제안했으나, 마지막에는 **우선 Payout의 상세 PDF를 제공하는 방향**으로 정리했습니다. Kay의 요청은 지급 여부를 확인할 방법이었으며, 새 체크박스 추가 자체를 요구한 것은 아니었습니다. 이 회의만으로 기존 지급 추적 필드의 유무를 판단하지 않습니다.

**추가 제안:** 영수증을 이메일로 보낼 수 있게 하는 아이디어도 나왔습니다. 자동 발송 여부, 발송 절차, 기존 Payout에 대한 소급 생성 범위는 확정되지 않았습니다.

**업무 배경:** 현재 건수는 수동 관리가 가능한 수준이지만, Notion 등에 나뉜 업무를 Salesforce로 옮겨 관리하려는 방향입니다. 특히 그룹헬스 리뉴얼 이메일의 반복 작업을 줄이는 효과를 기대했습니다.

필드 API 이름, 기존 보험의 회사 연결 보완 방법, 기존 Renewal에 대한 반영 범위는 이번 회의에서 확정하지 않았습니다.

### C1. 커미션 리포트의 기간 기준을 Payment Period로 통일

**상태:** Kay가 설명하고 수정 요청하기로 함

**녹취:** 00:24:25–00:27:53

- [ ] Agent Management와 비교하는 커미션 리포트의 기간 기준을 **Commission Date → Payment Period**로 맞춥니다.
- [ ] 같은 에이전트·기간을 선택했을 때 상세 대상과 금액이 일치하는지 확인합니다.

**불일치 사례:** 한 커미션의 Commission Date는 **8월 1일**, Payment Period는 **7월**이었습니다. 7월을 조회하면 Agent Management에는 포함되지만 리포트에서는 빠졌습니다. 양쪽이 서로 다른 날짜 기준을 사용하는 것이 원인이라는 설명에 합의했습니다.

늦게 들어오는 커미션도 있으므로 지급월 기준을 통일하기로 했습니다. 이는 **리포트 필터 기준 수정**이며 원본 Commission Date를 바꾸는 결정은 아닙니다.

**참고 제안:** 에이전트별 담당 보험과 고객을 확인하는 별도 리포트도 주원에게 부탁할 수 있다고 안내했습니다. 별도 리포트의 구체적인 구성과 제작 일정은 확정하지 않았습니다.

## 이전 작업의 상태 및 이번 회의에서 조정된 방향

- **BCBS 7월 커미션 연결 보정:** 앞자리 0과 유사 번호 매칭 문제로 약 120건의 오차를 잡았다는 개발자의 설명을 듣고 해당 안건을 마무리했습니다. 재발 방지 조치를 했다고 설명했으나, 정확한 대상·수정 건수·현재 연결 상태는 이번 문서 작성에서 재검증하지 않았습니다. *(00:20:37–00:21:57)*
- **갱신 생성 범위 90일:** 90일로 변경됐다고 회의에서 다시 확인했습니다. 새벽 5시 자동 실행도 안내됐으나 시간대는 녹취에서 특정하지 않았습니다. *(00:59:28, 01:01:21–01:01:34)*
- **예상 갱신이 목록에 없는 사례:** 종료일과 이미 수동 입력된 연도별 보험을 함께 확인했습니다. 같은 Policy Number의 기존 보험부터 조회했고, 이미 갱신 이력이 있는 점을 확인했습니다. 정확한 날짜는 녹취의 연도 표현이 불명확해 확정하지 않습니다. 데이터를 삭제하거나 상태를 바꾸는 작업이 완료됐다는 내용도 확인되지 않습니다. *(00:59:32–01:01:41)*

## 후속 확인 기준

아래는 회의 요구사항을 바탕으로 정리한 확인 항목이며, 아직 실행한 테스트 결과가 아닙니다.

- **이메일:** 회사 이름이 제목에 들어가고 Carrier가 보험사로 표시되며, 갱신 조건이 의도한 Quote와 일치하는지 확인합니다. Quote가 없거나 여러 개인 경우의 참조·안내 방식도 정해야 합니다.
- **기업 리드:** 요청한 회사 정보를 Lead에서 입력·저장할 수 있는지 확인합니다. 이후 전환 시 회사 정보가 어떻게 이어질지도 구현 과정에서 확인합니다.
- **리포트:** Commission Date와 Payment Period가 서로 다른 사례를 포함해, 같은 에이전트·지급월의 대상과 합계를 대조합니다.
- **지급 상세:** PDF의 개별 지급 내역과 총액이 해당 Payout과 일치하고, 특정 고객·보험의 지급 여부에 답할 수 있는지 확인합니다.
- **보험·회사 연결:** 한 Contact에 여러 Company가 연결된 사례에서 보험과 Renewal이 올바른 회사를 가리키는지 확인합니다.
- **Policy Number:** Kay의 실제 New·Edit 화면에서 입력 필드가 표시되고 값이 저장되는지 확인합니다.
