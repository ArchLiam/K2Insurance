# K2 Insurance 회의 정리 및 액션 아이템 — 2026-09-28

**참여자 표기:** Speaker 1(업무 운영) · Speaker 2(개발) · Speaker 3(일부 보조 발언, 신원 미확정)

**자료:** 제공된 회의 녹취, 00:00:00–00:19:02

**주제:** 리포트 필드 확인, 커미션 지급 표시, Insurance 이메일 Merge 필드와 고정 첨부, 가족 Lead 입력 및 회사 정보 전환, Agent Payout PDF·이메일

> 상태는 회의에서 설명·시연하거나 진행 상황을 보고한 내용을 기준으로 합니다. 문서 작성 과정에서 Salesforce Org의 데이터·설정·배포 상태를 별도로 검증하지 않았습니다. 음성 인식으로 흔들린 용어는 문맥에 따라 Insurance, Contact, Merge Field, Payout 등으로 정리했습니다. 정확한 필드명·버튼명이나 발언자의 신원을 확인할 수 없는 부분은 단정하지 않았습니다.

## 핵심 정리

1. **리포트의 숫자 불일치는 개발 담당자가 올바른 필드를 찾아 안내하기로 했습니다.** Formula 대신 Text 필드를 보고 있다는 문제가 제기됐으며, 이번 회의에서 정확한 필드나 수정 결과가 확인되지는 않았습니다.
2. **Commission Line의 Paid 표시는 Agent Management에서 Payout을 처리하면 반영된다고 안내했습니다.** 에이전트와 기간을 선택해 검토한 뒤 지급 처리하는 흐름을 확인했습니다.
3. **보험 가입 확인 이메일은 템플릿의 Related Entity Type을 Insurance로 설정해 보험 정보를 Merge하는 방법을 실습했습니다.** Contact의 추가 정보가 필요하면 항목을 전달하고 Insurance에서 참조할 수 있도록 보완하는 방안을 안내했습니다.
4. **고정 첨부는 이메일 작성 화면에서 파일을 붙이고 새 템플릿으로 저장한 뒤 재사용하는 흐름으로 확인했습니다.** 기존 템플릿에 저장한 첫 시도에서는 첨부가 다시 나타나지 않았습니다.
5. **가족을 함께 입력하는 Lead 기능에 긍정적인 피드백이 있었고, 회사 정보의 Lead 입력·전환 반영은 완료됐다고 보고했습니다.** 회사 정보는 Salesforce 내부 Lead에 추가한 상태이며 외부 리드폼에는 아직 반영하지 않았다고 설명했습니다.
6. **Agent Payout PDF 생성과 에이전트에게 보내는 버튼은 개발 진행 중입니다.** 운영 담당자는 PDF 생성만으로도 도움이 된다고 했고, 개발 담당자는 버튼으로 이메일을 보낼 수 있는 범위까지 작업 중이라고 설명했습니다.

## A. 개발 — 후속 작업

### A1. 리포트에서 사용할 정확한 필드 확인·안내

**상태:** 확인 후 안내 예정

**담당:** 개발 담당자

**녹취:** 00:00:00–00:00:27

- [ ] 숫자가 맞지 않는 리포트에서 현재 선택한 필드와 의도한 필드를 확인합니다.
- [ ] 올바른 필드와 선택 방법을 운영 담당자에게 알려줍니다.

**회의 내용:** 운영 담당자는 리포트의 해당 항목이 Formula가 아니라 Text로 되어 있다는 이야기를 전달했습니다. 개발 담당자는 잘못된 필드를 찾은 것으로 설명하며, 직접 확인해 올바른 필드를 알려주기로 했습니다. 운영 담당자는 안내해 주는 정도면 충분하다고 했습니다.

**미확정:** 리포트 이름, 해당 숫자, 필드의 레이블·API 이름은 녹취에서 특정되지 않았습니다. 이번 요청을 새 Formula 개발이나 필드 타입 변경으로 확정하지 않습니다.

### A2. Insurance 이메일에 필요한 Contact 정보 보완

**상태:** 필요 항목을 전달받으면 검토하는 조건부 후속 작업

**담당:** 운영 담당자(필요 항목 전달) → 개발 담당자(참조 필드 검토)

**녹취:** 00:06:03–00:07:43

- [ ] Insurance 템플릿에 넣고 싶지만 현재 선택할 수 없는 Contact 등의 정보를 운영 담당자가 정리해 전달합니다.
- [ ] 요청받은 항목을 Insurance에서 참조하고 템플릿에서 사용할 수 있도록 보완합니다.

**설명한 예시:** Contact에 있는 계약자의 생년월일을 사용하고 싶다면 Insurance에 `Policy Holder Birthday` 같은 표시 필드를 만들고, 해당 Policy Holder의 생년월일을 자동으로 가져오게 하는 방식입니다. 이 이름은 회의 중 예시이며 확정된 필드명이나 API 이름이 아닙니다.

**기록 범위:** 회의에서는 Related Entity Type을 Insurance로 선택했을 때 Insurance 필드를 사용하는 방법과 다른 객체의 정보를 가져오는 보완 방안을 설명했습니다. “Contact와 Insurance 필드를 함께 쓸 수 없다”는 발언을 Salesforce 이메일 템플릿 전체의 제약으로 확정하지 않습니다. 실제 템플릿 유형과 수신자·관련 레코드 문맥에 따른 사용 가능 범위는 별도 확인 대상입니다. 생년월일 필드를 이번 회의에서 실제로 생성한 것은 아닙니다.

### A3. Agent Payout PDF 생성 및 이메일 발송 기능

**상태:** 개발 진행 중 · 완성 후 안내 예정

**담당:** 개발 담당자

**녹취:** 00:16:52–00:17:40

- [ ] 지급 내역을 에이전트에게 전달할 수 있도록 Payout PDF 생성 기능을 완성합니다.
- [ ] 사용자가 보내기 버튼을 누르면 해당 에이전트에게 이메일로 전달하는 기능을 완성합니다.
- [ ] 완료 후 운영 담당자에게 사용 방법과 결과를 안내합니다.

**업무 흐름:** Agent Management에서 지급 처리 → Agent Payout 레코드 생성 → 지급 내역 PDF 확인 → 보내기 버튼으로 에이전트에게 전달하는 방향입니다.

**요청과 제안:** 운영 담당자는 “생성만 해주면 직접 보내도 된다”고 했습니다. 개발 담당자는 PDF 생성에 더해 버튼을 통한 이메일 발송까지 작업 중이라고 설명했습니다. 지급 처리 즉시 별도 조작 없이 자동 발송하는 것으로 합의한 것은 아닙니다.

**미확정:** PDF의 최종 양식, 이메일 제목·본문, 수신자 결정 방식과 완료 일정은 이번 회의에서 정하지 않았습니다. PDF 생성·발송 성공을 시연한 내용도 없습니다.

## B. 회의 중 안내·실습한 사용 방법

### B1. Commission Line의 Paid 표시

**상태:** 사용 방법 안내 및 이해 확인 · 실제 지급 결과 별도 미검증

**녹취:** 00:00:45–00:02:08

1. **Agent Management**에서 대상 에이전트를 선택합니다.
2. 지급 대상 기간을 선택합니다. 회의에서는 6월부터 8월까지를 예로 들었습니다.
3. 대상 내역을 검토하고 Payout 처리를 실행합니다.
4. 해당 지급에 포함된 Commission Line에 Paid가 표시된다고 안내했습니다.

운영 담당자는 이 동작으로 해당 지급 대상의 표시가 함께 바뀌는지 질문했고, 개발 담당자가 맞다고 답했습니다. 녹취에서는 실제로 지급을 확정한 뒤 Commission Line의 결과를 확인한 장면까지는 확인되지 않습니다.

### B2. 보험 가입 확인 이메일에 Insurance 정보 넣기

**상태:** Related Entity Type 변경 후 Insurance Merge 필드 선택 가능 확인

**녹취:** 00:02:15–00:07:56

**업무 목적:** 새 건강보험을 입력한 뒤 보험사, Policy Number, Premium, 보험 시작일 등의 정보를 고객에게 가입 확인 이메일로 보내려는 요청입니다. 기존에는 보험 정보를 이메일 본문에 직접 입력하고 있었습니다.

1. 사용할 이메일 템플릿을 엽니다.
2. 템플릿 Details의 **Related Entity Type**을 **Insurance**로 변경합니다.
3. 필요한 Insurance 필드를 **Merge Field**로 본문에 넣습니다.
4. 해당 Insurance 레코드의 이메일 작성 화면에서 템플릿을 불러와 사용합니다.

**회의 중 확인:** Related Entity Type을 바꾸자 Insurance 필드를 선택할 수 있다고 운영 담당자가 확인했습니다. 변경 전 값은 녹취에 “Read”로 기록되어 정확한 객체명을 확정하지 않습니다. 실제 이메일에서 모든 값이 채워지는지와 고객에게 발송됐는지는 확인되지 않았습니다.

### B3. 이메일 템플릿에 고정 첨부 포함하기

**상태:** 새 템플릿으로 저장한 뒤 다시 불러왔을 때 첨부가 나타나는 것을 회의에서 확인

**녹취:** 00:08:02–00:13:08

**실습 흐름:**

1. Insurance 레코드의 **Activity → Email**을 엽니다.
2. 사용할 이메일 템플릿을 삽입합니다.
3. 클립 모양의 **Attach File** 버튼으로 파일을 첨부합니다.
4. 템플릿 메뉴에서 **새 템플릿으로 저장**하는 방식으로 저장합니다.
5. 작성 화면을 닫고 새 이메일에서 저장한 템플릿을 다시 불러와 첨부를 확인합니다.

**시도별 결과:**

| 시도 | 회의에서 확인한 결과 |
| --- | --- |
| 파일 첨부 후 기존 템플릿에 저장 | 다시 불러왔을 때 첨부가 보이지 않았습니다. *(00:10:36–00:11:32)* |
| 새 템플릿으로 저장하는 방식으로 재시도 | 다시 불러온 뒤 “붙었다”, “되네요”라고 확인했습니다. *(00:11:32–00:12:52)* |

**기록 범위:** 녹취에서는 `Save New as Template` 및 유사 표현으로 안내했습니다. 정확한 최종 메뉴명·템플릿 이름과 파일명은 확인되지 않았습니다. 이번 결과는 해당 실습에서의 재호출 확인이며, 모든 템플릿 유형에서 동일하게 동작한다고 일반화하지 않습니다. 실제 이메일 발송·수신 결과는 확인하지 않았습니다.

## C. 기존 작업의 진행 상황 및 운영 피드백

### C1. 가족 Lead 입력과 회사 정보 전환

**녹취:** 00:15:34–00:16:50

- **가족 단위 Lead 입력:** 운영 담당자는 고객에게 링크를 보내 Lead를 받고 가족을 함께 입력할 수 있게 된 점이 업무에 큰 도움이 된다고 평가했습니다.
- **회사 정보 입력:** 개발 담당자는 Commercial 관련 회사 주소, EIN, SIC 등의 입력 항목을 Salesforce 내부 Lead에 추가했다고 보고했습니다.
- **Lead 전환:** 입력한 회사 정보가 전환 시 Contact·Account 등으로 넘어가도록 했다고 설명했습니다. 운영 담당자도 Lead에서 받은 정보가 이어져 업무가 수월해졌다고 했습니다.
- **외부 리드폼:** 회사 정보를 받는 외부 리드폼은 아직 만들지 않았다고 설명했습니다. 이번 회의에서 해당 폼의 제작 일정이나 담당을 새로 확정하지는 않았습니다.

기능 개선에 대한 보고와 사용자 피드백을 기록한 것이며, 모든 필드의 실제 전환 매핑이나 배포 버전을 확인한 결과는 아닙니다.

### C2. AI와 커미션 명세서 임포트

**상태:** 향후 검토 · 도입 결정 없음

**녹취:** 00:13:16–00:15:25

- 현재 제공된 기능을 대부분 활용하고 있으며, 현 단계에서는 충분하다는 의견이 있었습니다.
- AI를 활용해 커미션 명세서 임포트를 도울 수 있다는 가능성을 논의했습니다. 개발 담당자는 Salesforce에 직접 붙이는 방식과 개발 도구에 AI를 연결하는 방식의 차이를 설명했습니다.
- 운영 담당자는 비용을 들여 새 기능을 구매하기보다 당분간 수동 작업을 이어가겠다는 뜻을 밝혔습니다.
- 커미션 처리 방법이 개선되면 알려 달라고 요청했고, 개발 담당자가 동의했습니다. 제품, 비용, 구현 범위와 일정은 정하지 않았습니다.

### C3. 전반적인 사용 평가

**녹취:** 00:00:27, 00:13:16–00:13:49, 00:15:34–00:16:50, 00:17:47–00:19:02

운영 담당자는 요청했던 기능이 대부분 구현됐고 실제 업무에서 잘 사용하고 있다고 했습니다. 특히 고객 정보 수집과 Lead 전환으로 반복 입력이 줄어든 점을 높게 평가했습니다. 약 2년간 이어 온 개발·개선에 대한 감사와 지속적인 협업에 관한 대화로 마무리했습니다. 이 평가는 기존의 모든 개별 미완료 항목이 완료됐다는 확인으로 처리하지 않습니다.

## 후속 확인 기준

아래는 회의 요구사항을 바탕으로 정리한 확인 항목이며, 아직 실행한 테스트 결과가 아닙니다. 별도 기한은 회의에서 정하지 않았습니다.

- **리포트 필드:** 문제의 리포트와 필드를 특정하고 올바른 필드 선택 방법을 안내합니다. 같은 조회 조건에서 숫자 불일치가 해소되는지 확인합니다.
- **Paid 표시:** 선택한 에이전트·기간의 Payout에 포함된 Commission Line에 지급 상태가 반영되고, 지급 대상 밖의 라인에는 잘못 반영되지 않는지 확인합니다.
- **보험 이메일:** 선택한 Insurance의 보험사·Policy Number·Premium·시작일이 템플릿에 정확히 표시되는지 확인합니다. Contact 정보 추가 요청이 있으면 해당 계약자의 값이 표시되는지도 확인합니다.
- **고정 첨부:** 실제 사용할 파일로 새 템플릿을 저장하고, 새 이메일에서 다시 불러왔을 때 의도한 첨부가 유지되는지 확인합니다.
- **회사 정보 전환:** 내부 Lead의 회사 주소·EIN·SIC 등이 의도한 Contact·Account로 연결되는지 확인합니다. 외부 리드폼 반영은 별도 범위·일정이 필요합니다.
- **Payout PDF·이메일:** PDF의 상세 내역과 총액이 해당 Payout과 일치하고, 보내기 버튼으로 의도한 에이전트에게 해당 파일이 전달되는지 확인합니다.
